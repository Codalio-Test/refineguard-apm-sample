# Implementation Plan: RefineGuard APM

## Summary

Build a strictly on-premises (air-gapped, Purdue Level 3/3.5) predictive maintenance and asset
performance platform for refinery rotating machinery: historian ingestion (OSIsoft PI / Honeywell
PHD / OPC UA), an ISO 14224 / ISA-95 equipment digital twin, a multivariate Asset Health Index,
physics-informed failure-mode diagnostics, FFT spectral analytics, RUL prognostics, prescriptive
CMMS dispatch, and IEC 62443 audit / system governance. Backend is Rhino v4 on Rails (generated CRUD
for 17 organization-scoped models plus a small set of non-CRUD endpoints); the client is a Rhino
React SPA whose 18 pages, routes, shell and colour semantics come from the **already-approved UI
prototype** in `.codalio/ui-prototype/`, which is a locked constraint on routes and on the JSON
shape every endpoint must emit.

`server/.rhino/blueprints/_roles.yaml` + 17 model YAMLs are the blueprint contract; everything the
blueprint cannot express (computed attributes, aggregation endpoints, imports, hash-chained audit,
air-gapped auth hardening, keyboard layer) is enumerated under **Extras** and carried as
acceptance criteria `AC-109` … `AC-132`. Gaps found by the Phase 0 audit are carried as
`AC-133` … `AC-166` and itemised in **PRD gaps compensated** below.

## Extras (NOT covered by blueprint — develop stage implements these by hand)

Each Extra lists the model + action, the rule, where the code lives, and the acceptance criterion
that proves it.

### E1 — Computed attributes on `Asset` (and severity everywhere)
- **Model + action:** `Asset#show` / `Asset#index`; also `DiagnosticIncident`, `PrescriptiveAdvisory`,
  `ShiftLogEntry` (same pattern).
- **Rule:** emit `severity` ∈ {`critical`,`warning`,`healthy`,`info`} derived from the ISO state
  (Trip|Alarm → `critical`, Alert → `warning`, Normal → `healthy`), and emit `unit` = the plant unit
  code. Values must match the locked `SeverityBadge` keys or every badge falls through to the default
  style.
- **Where:** `server/app/models/asset.rb` (`rhino_computed_attributes`), and the equivalent block in
  `diagnostic_incident.rb`, `prescriptive_advisory.rb`, `shift_log_entry.rb`.
- **AC:** AC-109 (compensated G13); AC-145.

### E2 — Tag-keyed asset context
- **Model + action:** `Asset#index` with `filter[asset_tag]`.
- **Rule:** `/assets/:assetId/*` carries an asset **tag**, not a primary key. `asset_tag` must be in
  `rhino_filters` and unique per organization; the client resolves tag → id once and reuses it.
- **Where:** `server/app/models/asset.rb` (`rhino_filters :asset_tag`),
  `client/src/hooks/useAssetByTag.ts`.
- **AC:** AC-110, AC-148, AC-135.

### E3 — Fleet overview aggregate
- **Model + action:** `GET /api/{org}/dashboard/fleet_overview`.
- **Rule:** return the prototype's four KPI objects `{label, value, note, direction}` (Monitored assets,
  Requires attention, Critical, Fleet health index) **and** the PRD's ISO tallies (Total Monitored,
  Normal, Alert, Alarm, Trip) plus `unit_risk: [{name, exposure_percent}]`. Must use `Rhino.query`
  and gate on `AssetPolicy#index?`.
- **Where:** `server/app/controllers/api/dashboard_controller.rb`,
  `server/config/routes/rhino.rb` (or `config/routes.rb` under the tenant scope).
- **AC:** AC-111, AC-146, AC-36.

### E4 — Active anomaly queue
- **Model + action:** `GET /api/{org}/dashboard/active_anomalies`.
- **Rule:** return `[{id, issue, age, severity, asset_tag}]` where **`id` is the asset tag** so the

## Implementation order (recommended stage flow)

Aligned with `--pipeline` and the PRD's three phases.

**Stage 1 — Plan (this artifact set).** Blueprints + plan + acceptance criteria + index + UI handoff.

**Stage 2 — Develop.**

- *Phase A — scaffolding.* `bundle exec rails rhino:blueprint --dry-run`, then generate all 17 models,
  policies, migrations and seeders; add the User addendum migration; register every model in
  `config/initializers/rhino.rb`; draw the tenant route group; run `rails db:migrate`.
  Extend the generated models: `rhino_filters`/`rhino_sorts`/`rhino_search`/`rhino_includes` whitelists
  driven by the prototype's real reads, computed attributes (E1, E21), `Rhino::HasAuditTrail` on the
  four audit-bearing models. Re-run `bundle exec rails rhino:export_types` and commit
  `client/src/types/rhino.d.ts`.
- *Phase B — Extras.* E1–E24 in dependency order: E24 seeds first (role rows + `UsersRole` so
  `useRoles()` is never empty), then E19/E20 (auth + audit writer, everything else depends on them),
  then E16/E18/E17 (incident lifecycle), E15 (finding), E10/E8/E9/E21 (historian ingestion), E11/E12
  (asset hierarchy), E13 (model lifecycle), E14 (dispatch), E3/E4/E5/E6/E7 (aggregates + export).
  Every custom controller uses `Rhino.query` / `Rhino.scoped_query` and an explicit policy gate —
  no raw model constants, never a client-supplied `organization_id`.
- *Phase C — seeds.* Backfill `db/seeds.rb` with the PRD `sample_data` rows and the prototype-narrative
  assets so every locked fixture key resolves (E24, G15).
- *Phase D — tests.* Minitest per acceptance criterion: role × action (200/201/403), missing-permission
  403, cross-org 404, validation 422, every whitelisted filter/sort/include, and one test per Extra and
  per compensated AC.

**Stage 3 — Develop (UI) / UI-Integration.** Create the page files listed under **Screens** at the flat
routes from `ui-handoff.json` (with `AppOwnerProvider`, never upstream `BaseOwnerProvider`), then
vendor the prototype JSX verbatim into each `page_file` and swap only the data source — reads via
`data_contract`, writes via `action_contract`. The prototype's `styles.css` design tokens and
shadcn primitives under `components/ui/` are vendored as-is.

**Stage 4 — Test.** `bundle exec rails test` green; tighten anything broken; verify the host-runtime
contract proof (valid `POST /api/{org}/assets` as `admin` → 201; same call as `reliability_engineer`
→ 403; empty `asset_tag` → 422).

**Stage 5 — Review.** PRD compliance + test/coverage report against
`.codalio/acceptance-criteria.json` (166 criteria: 108 verbatim, 24 Extras, 34 gap-compensated).
